# Bitcoin Game

[![CI](https://github.com/AlexMerf/BitcoinGame/actions/workflows/ci.yml/badge.svg)](https://github.com/AlexMerf/BitcoinGame/actions/workflows/ci.yml)

Современная версия старой аркады «Kill Leonardo Di Caprio Now!» (1998): три вращающиеся биткоин-монеты, 120 секунд и цель — собрать 30 монет. Игра переписана с нуля на TypeScript, работает в браузере без бэкенда, собирается Vite и покрыта unit-тестами.

## Возможности

- Чистое разделение правил и рендера: `GameEngine` не знает о DOM и тестируется отдельно.
- 3 монеты одновременно, 17 кадров анимации, плавное покачивание и дрейф по полю.
- Таймер на 120 секунд, цель 30 монет, счётчик промахов и точность.
- Победа с экраном «Награда получена!», поражение по таймеру, рестарт и возврат на главный экран.
- Пауза по кнопке, `Esc` или при переключении вкладки.
- Звук на Web Audio API без аудиофайлов; отключается и запоминается.
- Лучший результат хранится в `localStorage`.
- Управление мышью, тапом и клавиатурой (`Tab` + `Enter`/`Space`).
- Адаптивная вёрстка: портретная раскладка, боковая панель на ноутбуках, мобильный экран.
- `prefers-reduced-motion`, видимый фокус, `aria-live` для озвучивания результата.
- Никаких внешних запросов: шрифт и ассеты лежат в бандле.

## Правила

- На поле одновременно три монеты. Каждая живёт 5–8 секунд.
- Клик или тап по монете — **+1** к счётчику. Монета исчезает и заменяется новой.
- Если монету не успеть собрать, она улетает и это считается **промахом**.
- Клик по пустому полю — тоже промах.
- Цель — 30 монет за 120 секунд. При достижении цели показывается экран награды.
- Если время вышло раньше, показывается результат и кнопка «Ещё раз».

Управление: мышь/тап, `Tab` + `Enter`/`Space` для клавиатуры, `Esc` или `P` — пауза, `Esc` на экране паузы — продолжить.

│  │  ├─ config.ts           # все настройки баланса
│  │  ├─ rng.ts              # mulberry32 + крипто-сид
│  │  ├─ format.ts           # форматирование времени и точности
│  │  ├─ types.ts            # Coin, GameStatus, ClickResult
│  │  └─ engine.test.ts      # 11 unit-тестов правил
│  └─ ui/

│     ├─ sound.ts            # короткие Web Audio сигналы
│     └─ storage.ts          # best score и mute в localStorage
├─ design/                   # исходные макеты дизайнера: screens/ и ui/
├─ docs/screenshots/         # скриншоты для README
├─ legacy/                   # оригинальная страница 1998 года и её старые копии
└─ .github/workflows/        # CI

Где что лежит:

- `src/assets/` — все изображения, которые попадают в production-сборку (кадры монеты и фон поля);
- `design/` — исходные макеты дизайнера, в сборку не попадают (см. [`design/README.md`](design/README.md));
- `docs/screenshots/` — скриншоты, используемые в этом README;
- `legacy/` — оригинальная страница 1998 года и её исторические копии (см. [`legacy/README.md`](legacy/README.md)).

### Почему без React

Игровое поле — это три абсолютно позиционированные кнопки и небольшая панель статистики. Фреймворк здесь добавил бы слой виртуального DOM и зависимость, но не решил бы ни одной задачи. Вместо этого логика вынесена в чистый класс `GameEngine`, а `GameView` синхронизирует состояние с DOM. Такой вариант проще тестировать, он меньше по размеру и оставляет полный контроль над анимациями.

### Игровой цикл

`GameView` запускает `requestAnimationFrame`, считает `dt` в секундах и ограничивает его 0.1 с, чтобы после фоновой вкладки не было скачка. `GameEngine.tick(dt)` двигает монеты, переключает кадры и уменьшает таймер; `renderCoins()` обновляет позиции, размеры и `src` спрайтов; `renderHud()` трогает DOM только при изменении значений.

### Настройка баланса

Все константы — в [`src/game/config.ts`](src/game/config.ts):

| Константа                                       | Значение  | Смысл                             |
| ----------------------------------------------- | --------- | --------------------------------- |
| `FIELD_SIZE`                                    | 800       | Логическая сторона поля           |
| `STARTING_COINS`                                | 3         | Монет на поле одновременно        |
| `GAME_DURATION_SECONDS`                         | 120       | Длительность раунда               |
| `TARGET_COINS`                                  | 30        | Цель для победы                   |
| `COIN_FRAME_SECONDS`                            | 0.05      | 20 кадров/с                       |
| `COIN_MIN_SIZE` / `COIN_MAX_SIZE`               | 128 / 200 | Размер хитбокса                   |
| `COIN_MIN_TTL_SECONDS` / `COIN_MAX_TTL_SECONDS` | 5 / 8     | Время жизни                       |
| `COIN_MIN_SPEED` / `COIN_MAX_SPEED`             | 6 / 18    | Дрейф, px/с                       |
| `COIN_REMOVE_DELAY_SECONDS`                     | 0.34      | Длительность эффекта исчезновения |

Точность считается как `collected / (collected + misses)`. Промахом считается и пустой клик, и улетевшая монета.

## Тесты и качество

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

`GameEngine` покрыт тестами на старт, отсутствие пересечений при спавне, анимацию, сбор монеты и респавн, координатные попадания, промахи, улёт монеты, победу, поражение, паузу и точность. Тесты не требуют браузера.

Стиль кода задают ESLint и Prettier; CI прогоняет все проверки на каждый push и pull request.

## Сборка и деплой

```bash
npm run build
npm run preview
```

Готовый сайт — статические файлы в `dist/`. Production-хостинг — Vercel: проект собирается автоматически при push в `main`. В настройках Vercel используются стандартные значения для Vite:

- Framework Preset: **Vite**
- Install Command: `npm ci`
- Build Command: `npm run build`
- Output Directory: `dist`

`base: './'` в [`vite.config.ts`](vite.config.ts) делает сборку переносимой: её можно разместить и в подкаталоге, и на любом другом статическом хостинге.

## Доступность и производительность

- Монеты — настоящие `<button>` с подписями; поддержаны `Tab`, `Enter`/`Space`.
- Диалоги — нативный `<dialog>` с фокус-ловушкой и `aria-labelledby`.
- HUD — семантические `<output>`; прогресс — `role="progressbar"`.
- `prefers-reduced-motion` отключает декоративные анимации, не ломая игровой процесс.
- Спрайты — обычные PNG с `image-rendering: pixelated`; шрифт подключается локально через Fontsource.
- Production-сборка: около 18 KB JS и 13 KB CSS до gzip (плюс кадры монеты и шрифт).

Оригинальная страница 1998 года сохранена в [`legacy/original-game.html`](legacy/original-game.html). Она открывается локально (двойным щелчком из `legacy/`) и использует общие графические ассеты приложения из `src/assets/`, но не входит в production-сборку. [`legacy/js/main.js`](legacy/js/main.js) и [`legacy/css/main.css`](legacy/css/main.css) — её старые копии, оставленные для истории; подробности — в [`legacy/README.md`](legacy/README.md).

Новая версия использует те же 17 кадров монеты (`src/assets/coin/frame-01.png … frame-17.png`) и фон `src/assets/game-field.png`, но не переиспользует старый код.
